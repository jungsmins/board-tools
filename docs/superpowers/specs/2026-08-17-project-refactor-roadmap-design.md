# 프로젝트 전체 리팩토링 로드맵 설계

> 이 문서는 [2026-08-17-mainpage-refactor-design.md](2026-08-17-mainpage-refactor-design.md)를 **대체**한다. 메인페이지를 독립 라운드로 다루던 이전 로드맵을 재검토해, 디자인 토큰·공용 프리미티브·라운드 구조를 처음부터 다시 설계했다. 이전 문서에 있던 브랜드 팔레트/라운드 순서 결정은 이 문서의 내용으로 갱신된다.

## 배경 및 목표

board-tools의 세 가지 도구(지도제작자들, 테라포밍마스, 아발론)는 기능적으로 완성되어, 이제 프로젝트 전체를 디자인/구조 양 측면에서 리팩토링한다. 실제 코드 변경은 사용자가 직접 진행하며, 이 문서는 **어떤 순서로, 얼마나 잘게 쪼개서, 어떤 디자인 방향으로** 진행할지에 대한 설계다.

### 이번 재설계의 두 축

- **디자인**: 브랜드 컬러 팔레트를 확장하고, 보드게임 테마가 느껴지는 톤(질감/타이포/인터랙션 디테일)으로 전체를 재구성한다. 3개 게임은 각자의 색상 아이덴티티를 유지하되, 공용 셸과 컴포넌트 프리미티브는 하나의 브랜드 톤으로 통일한다.
- **구조**: 프리미티브(재사용 컴포넌트)와 게임별 조합 컴포넌트를 명확히 분리하고, 인라인 데이터/반복 마크업/과대 컴포넌트를 정리하며, 테스트 인프라를 도입한다.

## 전체 라운드 구조

| 라운드 | 범위 | 목적 |
|---|---|---|
| **0. 재단** | 디자인 토큰, 공용 셸(Header/Footer), UI 프리미티브 킷, 메인페이지 | 이후 모든 라운드가 재정의 없이 그대로 가져다 쓸 공용 기반 확립 |
| **1. 지도제작자들** | 계절 테마 유지하며 라운드 0 프리미티브로 이전 | 컴포넌트 수가 가장 많고(17개) 이미 계절 테마 시스템이 있어, 프리미티브가 "게임별 오버라이드"를 잘 흡수하는지 가장 먼저 검증 |
| **2. 테라포밍마스** | 자체 색상 토큰 신설 + 프리미티브 이전 | 컴포넌트 수가 적어(6개) 가장 가볍게 진행 — 워밍업 겸 리듬 회복 |
| **3. 아발론** | 자체 색상 토큰 신설 + 프리미티브 이전 + 대형 컴포넌트 분해 | `PlayingRoom`(282줄), `CreateRoomForm`(266줄) 등 가장 얽힌 코드. 프리미티브가 이미 검증된 상태에서 마지막에 처리해 리스크를 낮춤 |
| **4. 정리** | 미사용 옛 토큰 제거, 전체 일관성 점검 | 모든 라운드가 새 토큰으로 이전을 마친 뒤 죽은 코드 제거 |

### 청크 분할 원칙

청크 하나는 다음을 만족해야 한다:
- 독립적으로 커밋 가능
- 그 자체로 `lint`/`tsc`/`test` 통과
- 브라우저에서 눈으로 검증 가능
- 이전 스타일과 공존해도 화면이 깨지지 않음 (옛 토큰을 당장 지우지 않는 지금 방식 유지)

목표 크기는 계획 문서 기준 대략 100~250줄. 라운드 0은 성격이 다른 5개 청크로, 게임 라운드는 보통 2~3개 청크로 나눈다 (상세는 하단 "라운드별 청크" 참고).

## 디자인 토큰

`src/app/globals.css`의 `@theme` 블록에 아래를 추가한다. 기존 `gradient-*`, `canvas`, `chrome`, `card-*`, `chip-*`, `title`, `rule` 토큰은 아직 참조 중인 컴포넌트가 있으므로 **이번에도 즉시 삭제하지 않는다** (라운드 4에서 일괄 정리).

| 토큰 | 값 | 용도 |
|---|---|---|
| `--color-brand-900` | `#123F3A` (다크 틸) | Header/Footer 배경, 강조 텍스트 배경 |
| `--color-brand-700` | `#1C7C74` (미플 틸, 베이스) | 주요 버튼 |
| `--color-brand-400` | `#5CB3A6` (라이트 틸) | hover 강조 |
| `--color-accent` | `#F2B33D` (머스타드) | 배지/아이콘 강조, CTA 포인트 |
| `--color-surface` | `#FFFBF2` (웜 크림) | 페이지 배경 |
| `--color-surface-raised` | `#FFFFFF` | 카드/패널 배경 (surface보다 한 단계 밝음) |
| `--color-ink` | `#241F1C` | 밝은 배경 위 본문 텍스트 |
| `--color-ink-muted` | `#7A6555` | 보조 텍스트, placeholder |
| `--color-danger` | `#E04830` | 위험 액션(삭제/나가기) — 브랜드 톤과 의도적으로 분리 유지 |

### 타이포그래피

- `--font-display`: 기존 로컬 폰트(온글잎긍정)와 `@theme`의 죽은 `'Noto Serif KR'` 선언이 서로 어긋나 있던 문제를 정리한다. **이번 라운드에서는 커스텀 폰트를 완전히 제거하고 시스템 기본 sans-serif로 통일**한다 (display 폰트는 추후 별도로 다시 결정).
- `--font-sans`: 지금까지 명시적으로 선언된 적이 없던 본문용 sans 폰트 토큰을 신설해 `body`에 명시적으로 적용한다. 값은 시스템 폰트 스택(`-apple-system, "Apple SD Gothic Neo", "Segoe UI", sans-serif` 등)으로 시작한다.

### 그 외 토큰 및 유틸리티

- **Radius 스케일**: `--radius-sm` / `--radius-md` / `--radius-full` — 지금 `rounded-lg`/`rounded-full`이 컴포넌트마다 즉흥적으로 섞여 쓰이는 것을 정리
- **Shadow 스케일**: `--shadow-card` / `--shadow-modal` — 지금 `shadow-md`/`shadow-2xl`이 즉흥적으로 쓰이는 것을 정리
- **`tabular-nums` 유틸리티**: 자원/점수처럼 실시간으로 바뀌는 숫자에 적용해 자릿수 변경 시 레이아웃이 흔들리지 않도록 함 (테라포밍마스 자원, 지도제작자들 점수에서 특히 유용)
- **grain 텍스처 유틸리티**: `--color-surface` 배경에 얹는 아주 옅은(3~5% opacity) SVG 노이즈 배경. 보드/카드 촉감을 저비용으로 표현
- **점선(perforated) 구분선 유틸리티**: 실선 대신 점선 구분선으로 점수판/카드 절취선 느낌을 냄
- 기존 `@layer utilities`의 애니메이션 패턴(`animate-season-image` 등)을 따라 `animate-pop-in`(진입 페이드인+슬라이드업, stagger 가능) 유틸리티를 추가하고, 메인페이지에 한정하지 않고 전 라운드에서 공용으로 사용

## 공용 셸/프리미티브 변경 방향

### Header / Footer
- 배경을 `bg-brand-900`로 변경, 기존 4색 그라디언트 바 제거
- Header 우측 텍스트는 `--color-accent`로 포인트
- 로고는 이미지 교체 없이 `--color-surface` 배경의 알약형(pill) 컨테이너로 감싸 어두운 헤더 위에서 자연스럽게 보이도록 처리

### UI 프리미티브 킷 (`src/components/ui/`)
게임 로직을 모르는 순수 프리미티브만 놓는다.

- **Button**: `variantClasses`의 하드코딩 hex 제거, 브랜드 토큰 기반으로 재정의. `active:scale-[0.97]` 눌림 피드백 추가. 게임별 오버라이드 패턴(`var(--color-cartographers-button-primary, ...)`)은 유지하되 fallback만 브랜드 토큰으로 교체
- **Card (신규)**: 지금 메인페이지 도구 카드, 각 게임의 스코어/자원 카드가 제각각 만들고 있는 "둥근 테두리+그림자+패딩 박스" 마크업을 공용화
- **Badge (신규)**: 지금 메인페이지의 플랫폼 chip 하나뿐인 뱃지 스타일을 공용화해 이후 게임별 태그(난이도/인원수 등)에도 재사용
- **Modal (신규)**: `ConfirmDialog`가 만드는 `fixed inset-0 + bg-black/45` 오버레이 패턴을 공용화
- **ConfirmDialog 리팩토링**: 지금 `Button`을 재사용하지 않고 색을 다시 하드코딩하는 문제를 고쳐, `Button`/`Modal` 프리미티브를 조합하는 형태로 재작성

### 메인페이지
- 상단 히어로 이미지 제거, Header 바로 아래 "도구함" + 도구 리스트 배치
- 신규 `ToolListItem` 컴포넌트로 인라인 마크업 분리 (세로 풀폭 row, 좌측 이미지 박스, 우측 제목/부제/설명/플랫폼 태그, hover 시 `translateX`+그림자 확대, 진입 시 stagger 페이드인)
- `TOOL_CARDS` 인라인 배열을 `src/constants/tools.ts` + `src/types/tools.ts`로 분리
- 이미지 자리의 텍스트 placeholder(`이미지`)를 임시 SVG 아이콘으로 교체

## 구조 리팩토링 원칙

1. **프리미티브 vs 조합 컴포넌트 분리**: `src/components/ui/`는 게임을 모르는 순수 프리미티브만. 게임 로직이 있는 조합 컴포넌트는 각 게임 폴더 유지.
2. **재사용 후보 판별 기준**: 2개 이상의 게임에서 비슷한 마크업이 반복되면 프리미티브 후보. 게임 1곳에만 있는 로직은 그 게임 폴더에 남긴다.
3. **150줄 초과 컴포넌트는 분해 대상**: `CreateRoomForm`(266), `PlayingRoom`(282), `JoinRoomForm`(150), `TerrainMark`(175) — 마크업/폼로직/서브컴포넌트 단위로 쪼갠다.
4. **인라인 데이터는 `constants/`+`types/`로 분리**하는 패턴을 전 게임에 동일 적용.
5. **`lib/` 폴더 네이밍 통일**: 현재 `lib/avalon-roles/api.ts`(폴더) / `lib/cartographers.ts`(단일 파일) / `lib/terraformingMars.ts`가 혼재 → 전부 `lib/<game-slug>/` 폴더 구조로 통일.
6. **클래스 조합은 전부 `clsx`** 사용, 템플릿 리터럴 조합 금지.

## 테스트 프레임워크

- **도구**: Vitest + `@testing-library/react` (+ jsdom)
- **범위**: 각 라운드에서 만들거나 수정하는 컴포넌트에 대한 기본 렌더링·인터랙션 테스트
- **E2E(Playwright 등)는 범위 밖**으로 명시적으로 제외

## 문서화 및 프로세스

- 이 마스터 로드맵 스펙 1개로 전체 방향을 관리한다.
- 구현 계획은 라운드 단위로, **해당 라운드 시작 시점에** 그때의 실제 코드를 보고 작성한다. 라운드 0의 계획만 이 문서와 함께 바로 작성하며, 라운드 1~4의 계획은 이전 라운드 결과(특히 프리미티브 인터페이스)가 확정된 뒤 그때그때 작성한다.
- 각 계획 문서 내부는 청크별로 섹션을 나눠 진행 상황을 체크리스트로 추적한다.
- 청크 하나 = 커밋 하나를 기본 단위로 하며, 리스크가 큰 청크(예: 3-2)만 선택적으로 브랜치를 사용한다.

## 검증 방식

- `npm run lint`, `npx tsc --noEmit` 통과
- 신규/변경 컴포넌트에 대한 `npm run test`(Vitest) 통과
- `npm run dev`로 브라우저 직접 확인 (라이트/모바일 뷰 포함, 지도제작자들 계절별 테마·아발론 실시간 동기화 등 정적 확인이 안 되는 부분 포함)

## 범위 밖 (Out of Scope)

- E2E 테스트(Playwright 등) 도입
- 실제 게임 표지 이미지 에셋 제작/교체
- 다크모드 (게임 중 어두운 방 사용성 관점에서 매력적이나, 이번 로드맵 범위를 벗어남 — 향후 라운드 후보로만 메모)
- Display 폰트 최종 결정 (이번엔 시스템 기본 sans로 임시 진행, 추후 별도 논의)
- Supabase 관련 로직 변경 (아발론 라운드에서도 UI/구조만 다루고 백엔드 로직 자체는 건드리지 않음)

## 성공 기준
